## 周1: 検証器の構築とベースライン確定

**やったこと**
1. `tests/check_layout.py` を新規作成（Playwrightで実ブラウザ計測）
2. 初回計測280件 → 検証器自身の誤検知を3種発見・修正:
   - 要素自身の背景色を無視して祖先だけ見ていた（紫タグ chip が誤検知）
   - `rgba()` 半透明背景をアルファ合成せず不透明扱い（tintボタンが比1.00と誤報）
   - グラデーション背景は文字色との比を計算できないのに白背景扱い
3. 修正後の正確なベースライン: **241件**

**ベースラインの内訳（何がどこで悪かったか）**
- コントラスト不足: 全ページ横断で約200件。最大の原因は和紙テーマ共通パレット
  （accent/warm/faint/negの4色が小さい文字で3.0〜3.4:1、必要4.5:1）
- 横はみ出し(モバイル375px): 入門(387px)・プロセス可視化(727px)・DC精度(489px)
- canvas文字: ラダーL0/L1/L2/L5/L6でCSS縮小後の実効文字サイズ3.7px（判読不能）
- タップ領域: スライダー高さ4〜16px（推奨28px以上）が7ページ

## 周2: 和紙テーマのコントラスト修正（241→92件）

**対象**: ladder_l0/l1/l2/l5/l6.html, learn_newton.html（共通パレットの6ページ）

**手法（アルゴリズムで色決定）**: 元色の色相・彩度をHSLで固定し、
白背景とのコントラスト比が目標値(4.9:1、淡色背景でも4.5:1を確保する余裕込み)を
満たす**最も明るい明度**を二分探索で求めた。「暗くしすぎない」を機械的に保証。

| 変数 | 旧 | 新 | 白背景比 |
|---|---|---|---|
| --accent(青緑) | #1f9e8a | **#197e6e** | 3.3 → 4.94 |
| --warm(琥珀) | #b3812f | **#926926** | 3.4 → 4.92 |
| --faint(薄墨) | #928f84 | **#737166** | 3.2 → 4.90 |
| --neg(紅) | #cf4f5f | **#ca3c4e** | 4.25 → 4.92 |

- rgba形式のtint背景・canvas塗りも新色RGBに統一（画面内の同色が2系統に割れるのを防止）
- activeボタンのtint背景はalphaを0.07→0.05に下げ、tint上でも4.5:1を維持
- 効果: ラダー5枚とNR講演のコントラスト指摘が**ゼロ**に。数値回帰45/45で計算は無傷

## 周3: モバイル対応（92→60件）

**A. ラダー5枚のcanvas文字（実効3.7px→8.5px）**
- 原因: 内部座標820〜840pxのcanvasが375px画面で0.35倍に縮み、10.5px文字が3.7px相当に
- 修正: `@media(max-width:700px)`で `.stage{overflow-x:auto}` + `canvas{min-width:680px}`
  → 図は横スクロールできる代わりに文字は0.81倍(8.5px相当)を下回らない

**B. タップ領域（4〜22px→28px以上）**
- ラダー5枚: `input[type=range]{height:32px}`
- プロセス可視化 speed-slider: トラック4px描画は `::-webkit-slider-runnable-track` に移し、
  input本体を28pxに（見た目不変で当たり判定だけ拡大）
- 可視化ツールのスライダー: 同じ手法で6px→28px
- v5のタブボタン: padding 3px→7px（フォントも0.6rem→0.7rem）

**C. 横はみ出し3ページ（犯人特定は「要素を消して測る」二分法で実施）**
- 入門(387px): selectの固有幅 → `max-width:calc(100vw - 64px)`
- DC精度(489px): グリッド項目の`min-width:auto`膨張 → `.metric{min-width:0}` +
  `.metric-value{overflow-wrap:anywhere}` + モバイルで`.card{overflow-x:auto}`
- プロセス可視化(727px): 三層の複合犯
  1. `.container{grid-template-columns:1fr 460px}`の固定460px列 → モバイルで1カラム化
  2. select固有幅428px＋header-controlsのnowrap → 幅キャップ＋flex-wrap
  3. footer(legend+スライダー)とstatus-barのnowrap → flex-wrap
  → scrollWidth 727→518→375（ビューポートぴったり）に段階的に解消

**周3後の状態**: 構造系指摘（はみ出し・canvas文字・タップ）は**全16ページでゼロ**。
残60件は全てコントラスト（ダーク系ツール・index・演習）＝周4の対象。

## 周4: ダーク系ツール＋index＋演習のコントラスト（60→0件）

**準備（動作）**: 違反箇所ごとの「実効背景色」をブラウザ実測で採取
（rgba半透明はアルファ合成、グラデーション背景は判定不能として除外）。
その際、検証器の残バグを1件発見・修正: グラデ背景ボタンの文字色を親背景と
比較してしまう誤検知（入門・可視化のbtn-primaryの比1.1という異常値はこれ。実物はシアングラデ+濃紺文字で問題なし）。

**手法**: ダーク背景上の文字は「明色化」方向の二分探索。同じ色が複数の背景に
乗る場合は**最も明るい背景**（比が最も厳しくなる側）を拘束条件に1色で解く。

| 色 | 旧 | 新 | 用途 | 比 |
|---|---|---|---|---|
| 共有slate | #64748b | **#8a98ab** | main.css/比較/v5/DC精度の説明文＋canvas文字 | 2.9〜4.2 → 4.7+ |
| 灰 | #868e96 | **#8b929a** | 入門の情報ラベル | 4.46 → 4.71 |
| 青 | #3b82f6 | **#5694f7** | accent-blue（演習タグ・リンク） | 3.9〜4.4 → 4.7+ |
| 紫 | #8b5cf6 | **#a27cf8** | accent-purple（演習・考察タグ） | 3.5〜4.3 → 4.7+ |
| 紫(LM法) | #a855f7 | **#b066f8** | 可視化のアルゴリズム色（JSデータ） | 4.10 → 4.72 |
| 石 | #78716c | **#908983** | 可視化のSOR法色 | 3.38 → 4.71 |

**個別対応（項目と理由）**
- index起動ボタン: 白文字on青(3.68)を「明青背景+ダーク文字」(6.1)へ。
  入門・可視化のグラデボタン（ダーク文字）と流儀を統一
- プロセス可視化リセットボタン: 背景#f85149→#e91309（白文字4.6）。
  ただし変数--accent-redは発散インジケータ・凡例が使うため明るいまま残し、ボタンだけ上書き
- 演習: `.ex-problem`の外にあるtool-link（本文中のツールへのリンク）が
  ブラウザ既定の青#0000ee（比1.98）のまま → 全tool-linkにaccent-blueを適用
